# medcheck 시스템 구조 — 도식 작성용 설명

도식을 그릴 분이 이 문서만 보고 그릴 수 있도록 쓴 것입니다.
숫자는 전부 실측값입니다.

---

## 한 줄 요약

약봉투 사진을 찍으면, 약 이름을 읽어 식약처 데이터에서 겹치는 약과
주의할 약을 찾아, 진료 때 의사에게 물어볼 문장으로 바꿔 줍니다.

**판정은 전부 로컬 데이터베이스에서 규칙으로 하고, LLM은 마지막 문장
다듬기에만 씁니다.** 사진도 약 이름도 서버 밖으로 나가지 않습니다.

---

## 전체 흐름 — 6단계

가로로 길게 늘어놓으면 이렇습니다.

```
[사진]  ->  ① 축소  ->  ② 글자 읽기  ->  ③ 줄 거르기  ->  ④ 약 찾기
                                                            |
                                              [사람이 확인]  <- 여기서 사람이 개입
                                                            |
                            ⑦ 문장 다듬기  <-  ⑥ 근거 붙이기  <-  ⑤ 판정
                                                            |
                                                         [결과 화면]
```

**④ 와 ⑤ 사이에 사람이 들어가는 것이 이 시스템의 핵심입니다.**
기계가 확신해도 사람이 확인하기 전에는 판정으로 넘기지 않습니다.

---

## 각 단계

### ① 축소
올라온 사진의 긴 변을 1280픽셀로 줄입니다.

요즘 폰 사진은 3000픽셀이 넘는데 그 해상도가 정확도를 올리지 않습니다.
오히려 저품질 사진에서는 압축 잡음을 뭉개 주어 **정확도가 올라갑니다.**
실측에서 원본 1400픽셀로는 못 읽던 약 이름이 1280픽셀로 줄이니
읽혔습니다.

### ② 글자 읽기 (OCR)
사진에서 글자 줄을 뽑습니다.

- **PaddleOCR 한국어 모델**을 ONNX 형식으로 변환해 씁니다.
- 서버에서 직접 돌립니다. 외부 API를 쓰지 않습니다.
- 모델 크기 29MB, 실행기 50MB. 무료 서버(메모리 512MB)에 들어갑니다.

### ③ 줄 거르기
읽은 줄에서 약 이름이 아닌 것을 뺍니다.

약봉투에는 조제일자, `1일 3회 식후 30분`, `흰색 정제`, `실온보관`,
`졸음이 올 수 있으므로 주의하세요` 같은 문구가 같이 인쇄됩니다.
약 이름은 `하세요`로 끝나지 않고 `보관`으로 끝나지 않습니다.
그런 패턴으로 거릅니다.

실측: 원문 195줄 → 108줄

### ④ 약 찾기 (매칭)
남은 줄을 식약처 품목 목록과 대조합니다. **여기가 2단 구조입니다.**

```
1단  DUR 카탈로그      19,441품목   상호작용·주의 정보가 있는 약
2단  허가 목록         46,554품목   식약처에 등록된 모든 약 (이름만)
```

**1단에 있으면 판정까지 가고, 2단에만 있으면 이름만 맞히고
"확인 대상 정보가 없습니다"로 표시합니다.**

2단이 필요한 이유: 실제 약봉투에 적힌 약의 약 절반이 1단 밖에
있습니다. 정장제, 유산균, 일반의약품이 그렇습니다. 2단이 없으면
그 약들이 화면에 안 뜨거나, 더 나쁘게는 **이름이 비슷한 다른 약이
대신 뜹니다.** 실측에서 항히스타민제가 스테로이드로 바뀌어 뜬 적이
있습니다.

**결과를 세 등급으로 나눕니다.**

```
자동 확정   확신이 높고 2등과 차이가 뚜렷함    체크된 상태로 표시
골라주세요   후보는 있으나 확신이 부족함        사용자가 고름
못 찾음     기준 미달                        검사에서 제외
```

### ⑤ 판정
사람이 확인한 약들을 놓고 다섯 가지를 봅니다.
**전부 로컬 데이터베이스 조회이고 규칙 기반입니다.**

```
같은 성분 중복    두 봉투에 같은 성분이 들어 있음
효능군 중복       같은 계열 약이 겹침                   7,064건 데이터
노인 주의        65세 이상 주의 대상                   1,983건 데이터
항콜린 부담       인지 저하와 관련된 성분의 점수 합계      493성분 척도
미평가           그 척도에 등재되지 않은 성분
```

**마지막 "미평가"가 중요합니다.** 점수가 0점인 것과 아직 평가되지
않은 것은 다릅니다. 합계를 하한값으로 표시하고 그 사실을 화면에
적습니다.

### ⑥ 근거 붙이기
각 판정에 출처를 답니다. 어느 데이터에서 나왔는지, 어느 기준을
썼는지를 화면에서 펼쳐 볼 수 있습니다.

### ⑦ 문장 다듬기 (LLM)
판정 결과를 의사에게 건넬 질문 문장으로 바꿉니다.

**이 단계에만 LLM을 씁니다. 그리고 없어도 동작합니다.**

- 약 이름은 기호로 가려서 보냅니다. 실제 이름이 밖으로 안 나갑니다.
- 돌아온 문장이 숫자를 바꾸거나 `중단하세요` 같은 말을 넣으면
  버리고 원래 문장을 씁니다.
- 호출이 실패하면 원래 문장이 그대로 나갑니다.

---

## 도식에서 강조하면 좋은 것 넷

**1. 사람이 중간에 들어간다**
④와 ⑤ 사이에 사람 아이콘. 기계가 확신해도 사람 확인 전에는
판정으로 안 넘어갑니다.

**2. 판정과 표현이 분리돼 있다**
⑤⑥은 규칙, ⑦만 LLM. 색을 다르게 하면 좋습니다.
LLM이 죽어도 결과가 나옵니다.

**3. 2단 카탈로그**
④ 안에서 위아래 두 층으로. 위층(DUR)은 판정까지, 아래층(허가목록)은
이름만.

**4. 데이터가 밖으로 안 나간다**
서버를 감싸는 테두리를 그리고, 그 밖으로 나가는 화살표가
⑦의 가려진 문장 하나뿐임을 보이면 좋습니다.

---

## 숫자 (도식에 넣을 것만)

```
식약처 DUR 데이터      19,441품목 · 상호작용 797,186건
식약처 허가 목록       46,554품목
항콜린 척도           493성분

실물 약봉투 10장 55개 약
  약 이름 찾음        45개 (82%)
  자동 확정          33개 (60%)
  틀린 약을 확정한 것    0개
```

**마지막 줄이 제일 중요합니다.** 복약 안전 도구에서는 못 찾은 약보다
틀리게 확정한 약이 위험합니다. 못 찾은 약은 사용자가 화면에서 알 수
있지만, 틀리게 확정된 약은 모른 채 의사에게 말하게 됩니다.
